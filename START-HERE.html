Set up your Mac

This package runs the course software inside Ubuntu, a Linux desktop opened through the Mac app UTM. A virtual machine (VM) is the saved Ubuntu computer. Its software is already installed; you only need to install UTM and open it.

Steps 1–4 happen on your Mac. Steps 5–6 happen inside the Ubuntu window.

1. Check your Mac

Choose Apple menu → About This Mac. You need an Apple M-series chip (M1, M2, M3, M4, M5 or later). This package does not support Intel Macs.

We recommend at least 16 GB memory. Allow 50 GB free disk space before downloading and extracting the package, with more space later for your work and backups. Internet access is needed to download the package. No programming tools need to be installed on your Mac.

Testing used an M5 Pro with 48 GB memory and macOS 26.6.2. Other Mac models still need testing. An 8 GB Mac has not been validated with these settings; ask the teaching team before installing on one.

2. Download and keep the folder in place

Download the UTM course package from the course website. It is several gigabytes, so let the download finish completely. In Finder, open Downloads and double-click the ZIP if it has not already been extracted.

You should see a folder called mac-arm-setup. In Finder, choose Go → Home, create a folder called COMP3431, and move the whole mac-arm-setup folder into it. Keep it here throughout the course. Avoid iCloud, OneDrive or other cloud-sync folders for a running VM.

Open mac-arm-setup. You should see START-HERE.html, start.command, backup.command, installer and vm. Do not try to run the VM from inside the ZIP.

3. Install UTM on your Mac

Open installer, then double-click UTM-4.7.5.dmg. In the window that opens, drag UTM onto Applications. Wait for the copy to finish, then eject the disk image using Finder. Open UTM from Applications once.

The included installer is the official UTM 4.7.5 release used for testing. If macOS asks whether you want to open the downloaded UTM app, follow its normal Open prompt. No App Store purchase is required. If UTM is already installed, open it and check its version using UTM → About UTM; ask the teaching team if you are unsure about a different version.

4. Open the course VM and check one Mac setting

In UTM, choose File → Open, then select vm/COMP3431-Mac-ARM.utm inside your mac-arm-setup folder. The VM should appear as COMP3431 Mac ARM. Use this prepared VM; you do not need to create a new VM or install Ubuntu yourself.

In the Mac menu bar, choose UTM → Settings → Display and leave Renderer Backend set to Default. This is a setting on your Mac. The VM already contains the tested processor, memory, networking and display settings; keep those settings as supplied.

Select COMP3431 Mac ARM and press Play. Wait for the Ubuntu login screen. Next time, you can double-click start.command or open the VM directly in UTM.

5. Log in to Ubuntu

Click inside the Ubuntu window. Select student and enter this initial password, all lower case:

Username: student
Password: comp3431

This password also works for sudo inside Ubuntu. It is separate from your Mac password. When a terminal asks for a password, no characters appear while you type; type it and press Enter.

You can change your Ubuntu password by running passwd in an Ubuntu terminal and following the prompts. Remember your new password and use it for future logins.

6. Check your first simulation

Inside Ubuntu, open COMP3431 Terminal from the applications list, or press Ctrl–Alt–T to open Terminal. Use the Ubuntu terminal for all course commands. Your Mac's Terminal is a different app and does not have the course software.

Run these commands one at a time, waiting for each to finish:

course doctor
course start

The first should print PASS. The second starts the robot simulator and opens RViz, the window showing the robot, laser readings and map. Wait for Ready in the terminal. The robot starts stationary.

Start the wall follower:

course wall-follow

You should see the robot move and the map grow. Simulation can run slower than real time. To stop wall following, then close the simulation:

course stop-robot
course stop

You are ready for the course once these checks succeed. When finished for the day, use Power Off in Ubuntu and wait until UTM shows the VM as Stopped. Closing a window alone is not the same as shutting down Ubuntu.

Working on the course

Start the VM with start.command, sign in to Ubuntu, and open COMP3431 Terminal inside Ubuntu. Run the commands below there, one line at a time.

Start, move and stop

course start
course wall-follow
course stop-robot
course stop

These commands start the maze and mapping, start wall following, stop wall following, then close the simulation. Use them as needed. Run course status to check whether the simulation is running. Use course reset to restart the current exercise at the robot's initial pose; saved maps and source edits are retained.

For keyboard control, start the simulation and run course teleop. Follow the keys printed in the terminal, then press Ctrl–C to leave keyboard control.

Edit and build your code

Your code is inside Ubuntu at /home/student/COMP3431/src. The wall-following and vision examples are in src/wall_follower. Open the workspace in the installed VS Code editor:

code ~/COMP3431

Save your edits, then stop the simulation and rebuild:

course stop
course build

Wait for the build to finish before running your code again. Open a fresh Ubuntu terminal after adding packages. Edit source files in src, not generated files in build or install.

The normal ros2 run, ros2 topic and ros2 node commands are available. For a messaging exercise, open two Ubuntu terminals. Run ros2 run demo_nodes_cpp talker in one and ros2 run demo_nodes_py listener in the other. Press Ctrl–C in each when finished.

Camera and marker exercise

course stop
course start vision
course wall-follow

Vision mode selects the 640 × 480 camera resolution expected by the supplied code. It opens a camera window and runs the marker-processing example. Finish with course stop.

For mapping exercises that do not use the camera, course start mapping --profile mapping disables it. Stop the current simulation before switching modes. This option is not a guarantee of faster simulation.

Save a map

While mapping is running, stop wall following and save your map:

course stop-robot
course save-map my-map

This creates ~/COMP3431/maps/my-map.yaml and ~/COMP3431/maps/my-map.pgm inside Ubuntu. Use a new name for each map you want to keep; existing maps are protected from overwrite.

Navigate with a saved map

course stop
course start navigation --map ~/COMP3431/maps/my-map.yaml

In RViz, select 2D Pose Estimate, then click and drag at the robot's current position and heading. Once the laser readings line up with the map, select Nav2 Goal, then click and drag at your destination. Choose a clear area of mapped floor.

Use RViz to cancel an active navigation goal. course stop-robot stops wall following; it does not cancel a Nav2 goal. course stop closes the whole simulation.

Back up your work to your Mac

Save your files in Ubuntu and run course stop. Leave Ubuntu and the VM running. On your Mac, open mac-arm-setup in Finder and double-click backup.command.

If macOS asks whether Terminal can control UTM, allow that specific Automation permission to use the backup tool. Wait for Saved: and a Finder window showing the new backup. The first backup can take a few minutes.

Each backup is a new dated .tar.gz archive in student-backups beside the Mac launchers. It contains your Ubuntu src, maps, tools and config folders. It does not include arbitrary files elsewhere in Ubuntu. Check that the backup exists before shutting down. Keep another copy of important backups somewhere safe.

To recover work, keep the backup archive unchanged and ask the teaching team to help extract the needed files into your Ubuntu workspace. Rebuild with course build after restoring source code. Do not replace the whole VM just to recover one file.

Finish your session

Run course stop, save and back up your work, then choose Power Off from Ubuntu's top-right system menu. Wait for UTM to show Stopped before moving or copying the VM folder.

Your work is stored inside vm/COMP3431-Mac-ARM.utm. Deleting that VM also deletes any work inside it that you have not backed up.

Help and Mac settings

Login details

On a fresh copy, the Ubuntu username is student and the password is comp3431, all lower case. Use your new password if you have changed it. Click inside the Ubuntu window before typing. This is separate from your Mac login.

A Mac command file will not open

To start the VM, use UTM → File → Open and select vm/COMP3431-Mac-ARM.utm.

For the backup command, open Mac Terminal using Command–Space → Terminal. Type zsh followed by a space, drag backup.command from Finder into Terminal, then press Return. You can use the same method with start.command. No Mac security setting needs to be disabled.

“course: command not found”

Open Terminal inside Ubuntu, not on the Mac. If needed, open COMP3431 Terminal from Ubuntu's applications list. The course software is installed inside the VM.

The robot does not move

It starts stationary. Wait for Ready, then run course wall-follow or course teleop. Do not start a second simulator in another terminal. Use course stop before switching exercises.

A simulation will not start

Read the error and log location printed in the Ubuntu terminal. Run course stop, then try course start once more. If it fails again, send the teaching team the error and the named log folder.

course doctor --verbose prints installation diagnostics. While a simulation is running, course doctor --live --verbose also checks real sensor data and transforms. The latest report is saved inside Ubuntu as ~/COMP3431/logs/doctor-latest.json. Logs are not included by backup.command; keep or copy the requested diagnostic report separately for support.

Saved VM settings

The package already saves the following settings. You normally do not need to edit them:

  • Apple Silicon ARM64 with hardware virtualisation.
  • 4 CPU cores, 6144 MB memory and a 64 GB virtual disk.
  • Shared networking for local simulation.
  • Display card virtio-ramfb, Retina mode off, automatic display resizing on.
  • Clipboard sharing on, with Ubuntu using the Xorg desktop session.

On each Mac, check UTM → Settings → Display → Renderer Backend: Default. This app-wide preference is not stored in the VM. Do not enable GPU acceleration for this course image. The supported display settings were checked with the simulator's laser and camera data.

If your Mac has only 8 GB memory, ask the teaching team for help. The supplied 6 GB VM allocation and a reduced 4 GB allocation have not been validated on an 8 GB Mac. Do not assign all your Mac's memory or CPU cores to the VM.

Small desktop, black window or slow simulation

Resize the UTM window; Ubuntu should adjust its desktop. Keep Retina mode off and use a modest resolution such as 1280 × 800. Ubuntu's Settings → Displays lets you select a resolution.

If you changed graphics settings, shut down Ubuntu, restore the settings above and start the VM again. A full VM shutdown is needed when changing its display hardware. Avoid force-stopping a working VM.

Simulation speed varies and can be substantially slower than real time. Use the default course start workflow, close other heavy apps, and keep enough free memory and disk space on the Mac. The additional Gazebo 3D window is optional and can be opened with course start --gui. The camera-off mapping mode is available for exercises that do not need vision; its speed benefit is not established.

UTM documents its display and Retina settings.

Mouse or keyboard captured by UTM

Press Command–Option to release input capture. Click inside the Ubuntu window to use its apps again. Ubuntu uses Ctrl for many shortcuts where Mac apps use Command.

Backup fails

Keep the VM running, wait for Ubuntu to finish booting, and try backup.command again. Check the Mac has free disk space. If you denied Terminal permission to control UTM, review System Settings → Privacy & Security → Automation on the Mac and allow Terminal to control UTM for this operation. No network share or SSH setup is required.

If it still fails, retain the error and tell the teaching team. A file ending in .partial is not a completed backup; wait for the Saved: message. Do not delete the VM while trying to recover work.

What has been tested

Login and the documented password, building all 14 course packages, ROS messaging, maze sensors, mapping, wall following, vision data processing, a short navigation goal and copying work to the Mac passed on an M5 Pro, 48 GB, macOS 26.6.2, using UTM 4.7.5.

Other Mac hardware, first-time installation on a second Mac, optional shared folders, physical robots and lab networking still need testing. The software is configured for simulation on this Mac. Follow the teaching team's instructions for physical-robot sessions. Software checks do not establish the correctness of assessed student solutions.

Ask for help

Contact the teaching team through the course's usual help channel. Include your Mac chip, memory and macOS version, the UTM version, the command or step that failed, and the full error text. For a simulation error, also include the log folder printed by the command.

Updates and removal

Back up work before updating Ubuntu or course packages, and follow the teaching team's update instructions. Do not change Ubuntu or ROS distributions to troubleshoot an exercise.

To remove the setup, back up your work, shut down Ubuntu and wait for Stopped in UTM. You can then remove the VM and its folder. Keep your backup archives if you still need the code and maps.
